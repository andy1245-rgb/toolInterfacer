# The fusion arm — what it measures, what it fails, and what the review found

2026-11-10. Artifacts: `bench/results/fusion-2026-11-10/` (the pre-registered run) and
`bench/results/fusion-sensitivity-2026-11-10/` (the fold-rule sweep, summaries only). Both
recompute offline from the repo; no server was up. Conditions were written to
`fusion-2026-11-10/prereg.json` **before** the run.

## The pre-registered run

`fusion|member=sklearn_text~vectorizer=tfidf_word~clf=logreg~features=rules|weights=0.5`
against `recorded|arm=floor_a`, five folds, seeds 0/1/2/4/7, stratified.

| | |
|---|---|
| reference, the 3B replayed | **325/415 = 78.31%** |
| `r_fusion`, equal-weight mean | **351/415 = 84.58%**, fixed 37 / broke 11, exact McNemar **p = 0.000222** |
| delta by fold seed | +26, +23, +26, +25, +25 |
| ledger | extract +12, glob +7, grep +6, reddit +6, read +3, **web_fetch −3, web_search −5** |
| `r_gate`, take the member below 3B confidence 0.38 | 330/415 = 79.52%, p = 0.267, **not significant** |

| condition, written before the run | result |
|---|---|
| C1 delta ≥ +20 rows | PASS (+26) |
| C2 McNemar p < 0.01 | PASS (0.000222) |
| **C3 no label worse than −3** | **FAIL — `web_search` nets −5** |
| C4 delta > 0 in ≥ 4 of 5 fold seeds | PASS (5 of 5) |

**Verdict: FAIL.** The accuracy is real and reproducible; the arm still sacrifices a class. That
is the same defect class as the `grep_only` rewrite, one digit smaller, and it is not shippable on
the strength of the headline.

## The sensitivity that changes the meaning

An adversarial review of the harness found that the fold rule alone moves a fitted arm by tens of
rows. So the same three arms were run under both rules, five seeds each, out of fold:

| arm, 2 ms, no base artifact | stratified (0,1,2,4,7) | mean | hashed | mean |
|---|---|---:|---|---:|
| `member` — tfidf_word + cue features | 314, 312, 308, 308, 307 | 309.8 | 306, 305, 307, 305, 309 | 306.4 |
| `member_scaled` — same, `feature_scale=maxabs` | **349, 351, 347, 331, 336** | **342.8** | 318, 336, 317, 330, 342 | 328.6 |
| `r_fusion` — mean@0.5 with the 3B | 351, 348, 351, 350, 350 | 350.0 | 339, 347, 352, 347, 344 | 345.8 |
| the 3B, fixed | 325 | 325.0 | 325 | 325 |

Three things fall out, in order of how much they should change a decision:

1. **`feature_scale=maxabs` moves the member by 35 rows** (314 → 349 at stratified seed 0). One
   undocumented key, larger than the entire fusion delta. Until that key is pre-registered with
   its selection cost, no part of the fusion's +26 can be attributed to fusion rather than to the
   member's configuration.
2. **The member alone beats the 3B** at 349/415 = 84.1% in 2 ms, with no base artifact, no
   recording, no server. At stratified seed 0 the fusion is 2 rows better; at seed 1 the member
   is 3 rows better (351 vs 348). The fusion's advantage over the best single cheap arm is
   **0 to 7 rows**, not 26.
3. **The fold rule is an instrument, not an implementation detail.** It moves the fusion by ~4
   rows and the member by up to 26. C4 varies seeds within one rule and therefore cannot detect
   a rule change of the same size as the effect it guards. Every artifact now records
   `dataset.cv_rule` and `grouped_cv.stratified`; quote them beside the number.

## What is established, and what is not

* **Established:** a 2 ms TF-IDF-plus-cue-features logistic arm reaches 84% out of fold on this
  corpus, against the served 3B's 78.3%, at two fold rules and five seeds. That is the cheapest
  competitive arm in the repo and it does not need a model file.
* **Established:** the 3B's own confidence is a usable correctness signal (median 0.895 on rows it
  gets right, 0.395 on rows it gets wrong, AUC 0.858), which is why any fusion form moves at all.
* **Not established:** that fusion is what buys the gain. A competing explanation — a better
  member — is worth 35 rows on its own and has not been excluded.
* **Not established:** that this survives the corpus. 86% of v3's rows contain a literal slot
  value from `tools/distill/frames.py`, and the cue table shares a source with the distiller. The
  transfer test to v2 is +2.0 points at n=150, p=0.375: same sign, no power.

## The next measurement, in one line

Pre-register the member's configuration **including `feature_scale`**, then run
`recorded|arm=floor_a` vs `member_scaled` vs `r_fusion` on 5 fold seeds × 2 fold rules with C3
attached to all three arms. Pass iff the fusion beats the best single arm by ≥ 10 rows at
p < 0.01 in both rules. `docs/direction-adjudication.md` §5 stands as the target: until a member
is fixed before the run, every number here is a knob reading.

## What the review changed in the harness

Eleven defects, all fixed, each with a test that fails when the fix is reverted:

| | |
|---|---|
| `--fit-on X --split X` fitted and scored the same rows and reported 100% | refuses on an id overlap |
| a row that never produced a prediction was counted as a miss with no error count anywhere | `n_errors` per arm, printed in the table, stored in the summary |
| `--order` was accepted for `fusion`, whose base is a frozen replay | the refusal keys on the `replays_a_file` capability, not on a signature |
| `base=recorded~arm=grep_only` silently selected `floor_a` | the base spec expands `~` and unknown keys are refused |
| a duplicate row id in a base artifact silently overwrote the earlier row | raises |
| `--aa` on a fitted or CV reference reported a 100% flip rate | refits the A/A instance the same way, and says so |
| `--cv` left non-fitted arms in-sample beside out-of-fold ones with no marker | prints the skip and stores `grouped_cv: null` |
| a `seeds_*` condition on a run without `--cv` failed for an operational reason | refused with the reason |
| a committed artifact carried an absolute machine path and broke `test_no_personal_paths` | the dataset source is stored repo-relative |
| `fusion`'s docstring quoted another experiment's numbers | it now quotes this artifact |
| `coverage_at_precision`'s threshold did not define its set; `gate_verdict` cleared on 1 row at a 0 floor | both fixed earlier in the same run, both re-verified |

The artifact was regenerated after those fixes and reproduces the same numbers to the row:
351/415, C3 FAIL, `VERDICT: FAIL`.

## The decisive follow-up: fusion against the member, pre-registered

Conditions written to `bench/results/fusion-member-prereg.json` **before** the run, with the
member's spec frozen (`vectorizer=tfidf_word|clf=logreg|features=rules|feature_scale=maxabs`) and
the pass rule requiring **both** fold rules to clear. Reference is the member, not the 3B, because
that is the competing explanation.

| rule | member (2 ms) | fusion | fusion vs member | conditions |
|---|---:|---:|---|---|
| **stratified** | **349/415 = 84.1%** | 342/415 = 82.4% | **−7 rows**, p = 0.464 | C1 −7 FAIL, C2 0.464 FAIL, C3 −12 FAIL, C4 0/5 FAIL |
| **hashed** | 318/415 = 76.6% | 334/415 = 80.5% | +16 rows, p = 0.097 | C1 +16 PASS, C2 0.097 FAIL, C3 −15 FAIL, C4 5/5 PASS |

**Verdict: FAIL under both fold rules.** Under stratified folding the fusion is *worse* than the
member by 7 rows. Under hashed folding it is 16 rows better but not significantly, and it takes
15 net rows out of one label to do it. The fusion was the top-ranked direction in `docs/direction-adjudication.md` and it does
not survive being compared to the arm it was supposed to improve on.

The member against the 3B, for completeness, and it is not clean either:

| rule | member vs 3B | p | worst label |
|---|---:|---:|---|
| stratified | **+24 rows** (fixed 34 / broke 58) | **0.016** | **−17** |
| hashed | −7 rows (fixed 55 / broke 48) | 0.555 | −19 |

So the cheapest arm in the repo beats the served 3B by 24 rows **under one fold rule and not the
other**, and it sacrifices a class while doing it. That is a lead, not a result: it needs a third
corpus and a pre-registered fix for `decide_extract` (the label it gives up) before anyone calls
the 3B replaceable.

Nothing here is a shipping decision. What is settled is negative and useful: **fusion is closed.**

## The mask attempt: it does not reach the failure, and it costs 21 rows

The failing condition was C3 — `web_search` netting −5 — and the proposed repair was to mask the
text member's candidate set to the labels its own confusion matrix says it can answer. Two
implementations were run on the same folds, with the rule declared in
`bench/results/fusion-masked-prereg.json` before either: **the member may vote for label L only
when, on the rows where it votes L, it is right more often than the base arm is** — tallied from an
inner five-fold over exactly the rows handed to `fit`, minimum 10 such rows.

| form of the mask | accuracy | vs 3B | C1 | C2 | C3 | C4 | web_search |
|---|---:|---:|---|---|---|---|---:|
| none (the original run) | 351/415 = 84.6% | **+26** | PASS | PASS | **FAIL −5** | PASS | −5 |
| pruned distribution | 331/415 = 79.8% | +6 | FAIL | FAIL | FAIL −8 | PASS | −8 |
| member abstains when its top is masked | 330/415 = 79.5% | +5 | FAIL | FAIL | **FAIL −6** | PASS | −6 |

Both masked forms fail C1, C2 and C3, and both are **worse than no mask at all**. The second is the
faithful reading of the rule — the first gave the mask a second job it should not have had, and its
numbers are kept in the record because the mistake is instructive: **in a mean blend, pruning a
label from one member's distribution is not "not voting for it", it is voting against it.** Removing
the member's `web_search` mass cost `web_search` 8 net rows instead of saving the 5 the mask
existed to save.

### Why the mask cannot work here

The brief's diagnosis was that the member votes `web_search` where it has no competence. Measured
on the failing rows, the opposite is true: **the member never votes `web_search` on a row that
breaks.** It never happens once in 415 — the eleven broken rows are

```
true           3B              member           fused
web_search     web_search      reddit_digest    reddit_digest     ×6
web_fetch      web_fetch      decide_extract   decide_extract    ×3
decide_pick    decide_pick    filesys_glob     filesys_glob      ×1
filesys_grep   filesys_grep   filesys_read     filesys_read      ×1
```

The damage on `web_search` is the member voting **`reddit_digest`** on `web_search` rows: 6 of 52,
where the 3B was right. And `reddit_digest` is a label the member is *good* at — 42 right against
the base's 38 on the rows where it votes it — so every competence rule that can be computed keeps
it in the candidate set. The failure is a **pair**, `reddit_digest` claimed on `web_search` rows,
not a label. A per-label mask cannot see a pair, and the row-level information that would tell the
two apart is the true label, which is exactly what is not available at prediction time.

### The residual, and the stop

C3 fails at **−6 net rows on `web_search`** and −3 on `web_fetch`, with the mask in place. Per the
brief, this stops here rather than turning into a search for a rule that passes. Three things are
now known that were not:

1. The mask's own tally is unstable by fold: five folds at seed 0 keep 4, 3, 4, 3 and **1** labels,
   on 20–40 rows per label. A per-fold learned mask injects as much variance as it removes.
2. The mechanism is a confusion pair, not a weak label, so option (1) of the brief is closed and
   option (2) — per-label weights from out-of-fold skill — would inherit the same blind spot, since
   it also assigns weights per label rather than per pair.
3. The fusion's +26 depends on the member voting everywhere, including where it is weak. Any
   restriction that removes the member's weak votes also removes the votes that carry the gain,
   because the same member is wrong and right on the same label depending on the row.

That leaves option (3) from the brief, and it is not tuning: route `web_search` and `web_fetch` by
the 3B alone, take the member's vote everywhere else, and re-pre-register the four conditions
against the *member* as well. That is a different arm with a smaller claim, and it is the operator's
call, not this job's.

---

## REFUTED: the mask hypothesis. Do not retry it.

Recorded here so nobody spends another night on it. The hypothesis was that the text member votes
`web_search` where it has no competence, and that masking its candidate set to labels it can answer
would repair C3. **Every part of it is false, and both implementations made things worse.**

**The member never votes `web_search` on a row that breaks.** Not once in 415 rows. The eleven
broken rows, seed 0, unmasked arm:

| true label | 3B | member | fused | count |
|---|---|---|---|---|
| `web_search` | `web_search` ✓ | **`reddit_digest`** | `reddit_digest` ✗ | **6** |
| `web_fetch` | `web_fetch` ✓ | `decide_extract` | `decide_extract` ✗ | 3 |
| `decide_pick` | `decide_pick` ✓ | `filesys_glob` | `filesys_glob` ✗ | 1 |
| `filesys_grep` | `filesys_grep` ✓ | `filesys_read` | `filesys_read` ✗ | 1 |

**The damage is `reddit_digest` claimed on `web_search` rows** — 6 of the 52 `web_search` rows,
where the 3B was right. And `reddit_digest` is a label the member is *good* at: 42 right against
the base's 38 on the rows where it votes it (seed 0). Every competence rule that can be computed
from a confusion matrix keeps `reddit_digest` in the candidate set, so no mask built the way the
brief described can remove this confusion.

**Both masked forms were worse than no mask**, on the same folds, under a rule declared before
either run (`bench/results/fusion-masked-prereg.json`: a label stays only if the member beats the
base on the rows where it votes it):

| form of the mask | accuracy | vs 3B | C1 | C2 | C3 | C4 | `web_search` |
|---|---:|---:|---|---|---|---|---:|
| none | **351/415 = 84.6%** | **+26** | PASS | PASS | FAIL −5 | PASS | −5 |
| pruned distribution | 331/415 = 79.8% | +6 | FAIL | FAIL | FAIL −8 | PASS | −8 |
| member abstains when its masked top is the answer | 330/415 = 79.5% | +5 | FAIL | FAIL | FAIL −6 | PASS | −6 |

The first form carries a second lesson worth keeping: **in a mean blend, pruning a label from one
member's distribution is not "not voting for it", it is voting against it.** Removing the member's
`web_search` mass cost `web_search` 8 net rows instead of saving the 5 the mask existed to save.
The second form is the faithful reading — the member simply has no opinion when it cannot name its
top choice — and it is still 6 rows short, because the votes that damage `web_search` are
`reddit_digest` votes, which the mask keeps.

A third observation, which is why the mask was also unstable: the per-fold tallies keep 4, 3, 4, 3
and **1** labels across five folds at 20–40 rows per label. A learned per-label mask injects as
much variance as it removes. The per-fold masks are in the artifact
(`grouped_cv.per_seed.*.fold_predictors`).

## Option 3 — the base owns `web_search` and `web_fetch`. **All four conditions pass.**

Declared before the run in `bench/results/fusion-option3-prereg.json`: when the base's own top
choice is `web_search` or `web_fetch`, the member is not consulted and the base answers alone. On
the other six ops the equal-weight mean is unchanged. No mask, no weight tuning, same member spec,
same folds, same seeds.

| | |
|---|---|
| accuracy | **349/415 = 84.1%** (3B: 325/415 = 78.3%) |
| paired | fixed 26, **broke 2**, **+24 rows**, exact McNemar **p = 3.03e-06** |
| fold seeds | +24, +22, +23, +24, +25 — positive in **5 of 5** |
| ledger | extract +10, glob +5, grep +4, read +3, reddit +1, web_search +1, pick 0, web_fetch 0 |
| **C1** delta ≥ +20 | **PASS** (+24) |
| **C2** p < 0.01 | **PASS** (3.0e-06) |
| **C3** no label worse than −3 | **PASS** (worst label 0) |
| **C4** positive in ≥4 of 5 seeds | **PASS** (5 of 5) |
| floor gate | PASS (+24 vs 3 needed) |

**Both broken rows are inside the two owned ops** (`decide_pick` and `filesys_grep` each break once
and are netted out by their own fixes), so the protection covers the damage without removing the
gain: 26 fixed against 2 broken, where the unprotected arm was 37 fixed against 11.

### What this pass does and does not mean

It is a pass against **the 3B**, which is what the four conditions say, and the arm is now honest
about its ledger for the first time.

It is **not** a win over the cheapest single arm. Run head to head on the same folds, seed 0:

| arm | seed 0 | seeds 0,1,2,4,7 | mean | spread |
|---|---:|---|---:|---:|
| `member_scaled` — one 2 ms classifier, no base artifact | 349 | 349, 351, 347, **331**, 336 | 342.8 | **20** |
| `fusion … |protect=web_search,web_fetch` | 349 | 349, 347, 348, 349, 350 | **348.6** | **3** |

Paired at seed 0: **fixed 32, broke 32, delta +0, p = 1.0000.** The protected fusion and the single
scaled member are the same arm on that fold assignment.

What the fusion buys, then, is not accuracy at a fixed fold assignment — it is **stability across
fold assignments**: the member alone swings 20 rows depending on how the corpus is folded, and the
protected fusion swings 3. That is a real property and a different claim from "+24 over the 3B",
and it needs its own pre-registration before anyone quotes it as one.
