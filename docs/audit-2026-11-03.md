# Audit — the implementation against spec 1.0

Audited 2026-11-03 on branch `ov-audit` (from `main` @ 1a7c8fe).
Method: every file below was read in full; the test suite was run; the service was
started and probed over HTTP; the wheel was built and imported; the extension was
type-checked and both check scripts were executed. No code was changed.

Baseline reproduced: `python3 -m pytest tests/ -q` → **326 passed, 159 subtests
passed, 2.86 s**. Line coverage measured with stdlib `trace` (no `coverage` module
installed on this box).

---

## Verdict

**Not publishable today.** The engine is real — runner, gates, budget, cache, pair/cascade, CLI adapter, L1 bridge, 326 tests — but delivery breaks at three points.
**1. Install is broken**: `pip install .` yields a wheel with 2 of 53 modules; `import ti.service_entry` → `ModuleNotFoundError: No module named 'ti.conf'` (`pyproject.toml:14`).
**2. The extension cannot load or type-check**: `typebox` and both `@earendil-works/*` are undeclared → 66 `tsc` errors and `contract-check.ts` never reaches its first assertion (`pi-extension/package.json:10`).
**3. The headline L2 template cannot run**: it names ops `__decide_extract__`/`__decide_pick__` that do not exist, so every "research …" intent errors on step 1 (`templates/research.py:19,23`).
**Behind them, a fourth blocker**: the default `pair` backend needs both a local model and an API key, so with neither, every singular L1 call is also `status:"error"`.

## Findings

Severity: **blocker** = a stranger cannot get to a working first run · **major** =
works, but a documented contract is violated or a real input breaks/hangs it ·
**minor** = wrong number, dead code, or a defect with a narrow blast radius.

### Blockers

**1. [blocker] The wheel ships 2 of 53 modules and cannot be imported.**
`pyproject.toml:14` declares `packages = ["ti"]`, which lists the top-level package
only; no subpackages and no package data. Built with `python3 -m pip wheel .` the
artifact contains exactly `ti/__init__.py` and `ti/service_entry.py` — no `ti.core`,
`ti.conf`, `ti.ops`, no `conf/defaults.json`. Extracted and imported:
`from ti.http.api import serve` → `ModuleNotFoundError: No module named 'ti.http'`;
`import ti.service_entry` → `ModuleNotFoundError: No module named 'ti.conf'`.
There is also no `[project.scripts]`, so the documented entry point
`python3 -m ti.http.api` exists only when run from a source checkout with
`PYTHONPATH=service`.
*Minimal fix:* `[tool.setuptools.packages.find]` with `where = ["service"]`, add
`[tool.setuptools.package-data] ti = ["conf/defaults.json"]`, and add a console
script. Verify with `pip wheel` + import in a clean venv.

**2. [blocker] The extension cannot be loaded and cannot be type-checked.**
`pi-extension/package.json:10` declares `"dependencies": {}` and only
`typescript` as a devDependency. Four imports are unresolvable: `typebox/value`
(`bridge.ts:1`, `contract-check.ts:6`), `@earendil-works/pi-ai`
(`contract.ts:7`, `index.ts:1`), `@earendil-works/pi-coding-agent`
(`index.ts:2`, `session_push.ts:3`), and — through the absent `@types/node` —
every `node:` builtin and `process`. Measured: `tsc --noEmit` reports **66 errors**;
adding only `@types/node` leaves **24** (6 × TS2307 missing module, 18 × TS7006
implicit-`any` cascade from those). The two genuine-looking ones (`capture.ts(112,2)`
TS2322, `lifecycle.ts(33,91)` `NodeJS` namespace) both disappear once `@types/node`
is present, so they are artifacts, not logic errors. `scripts/contract-check.ts`
aborts before its first assertion: `ERR_MODULE_NOT_FOUND: Cannot find package
'typebox'`. So the contract check **proves nothing as shipped** — it cannot run.
*Minimal fix:* declare `typebox`, `@earendil-works/pi-ai`,
`@earendil-works/pi-coding-agent` as deps (or peers) and `@types/node` as a devDep;
add `"types": ["node"]`; commit the lockfile.

**3. [blocker] The research template names ops that do not exist.**
`templates/research.py:19,23` use `op="__decide_extract__"` and
`op="__decide_pick__"`; the registry has `decide_extract` and `decide_pick`
(`ops/decisions.py:65,78`, confirmed by a live `GET /health`). Live result of
`useTool("research the qwen3.5 finetune results")`:
`{"status":"error", "error":"\"unknown op '__decide_extract__'; known: [...]\""}`,
`hops: []`, at 0.0 ms — it dies on step 1. `mode:"plan"` advertises the same
broken plan *and* reports `"ops_available": true` (`service_entry.py:175`), so the
offline inspection mode actively certifies a plan that cannot execute.
*Minimal fix:* rename the two ops in `research.py`; add a plan test that asserts
every `step.op` is in `all_ops()`.

**4. [blocker] The shipped default decision backend needs two things a fresh clone
does not have.**
`conf/defaults.json` sets `backends_in_use.choice = "pair"` with `stage1 =
d1_systemone` (a llama.cpp server on `127.0.0.1:8080`) and `stage2 = openrouter`
(needs `TI_OPENROUTER_API_KEY`). With both absent — the normal state of a new
checkout — `pair.choice` raises `RuntimeError("pair: no stage produced a choice")`
(`pair.py:189`). Live, on a clean start:
`useTool("read the file we discussed")` → `{"status":"error", ..., "error":"pair: no
stage produced a choice"}` after a 3.4 ms glob. Only intents that route to a
*listing* work out of the box; anything singular is dead.
`docs/decision-pair-vs-hosted.md` justifies the `pair` default on the grounds that
"the pair degrades to local and keeps answering" — true only when a local model is
actually serving, which the same document's failure table assumes. The zero-config
case is not covered by that argument.
*Minimal fix:* ship a `fixture`/`rule_*` fallback (or an explicit `degraded` answer)
when neither stage answers, or default `backends_in_use.choice` to something that
works with no model, and document the model as required.

### Major

**5. [major] Ask-back is specified, plumbed, and never reached — `need_input` is
returned without a question.**
Spec §2/§4: after best effort the tool returns `{status:"need_input", question…}`,
capped at `max_asks = 2`. Reality:
- `http/api.py:36` calls `use_tool(body, dry=dry)` — `on_ask` is omitted, so
  `_run_steps`'s `ask()` immediately raises `MaxAsksReached`
  (`service_entry.py:84-89`), `_handle_block` returns `False`, and the run becomes
  `degraded:true, status:"done"`. Verified live with a fixture backend forced to
  conf 0.5: `{"status":"done","degraded":true,"assumptions":["content: gate
  unresolved, using the best guess …"]}`. The `Question`/`AskBack` machinery exists
  but has no producer and no transport.
- The one place that *does* set `status:"need_input"` is `runner.py:73` (hop budget
  exhausted before the first hop), and it always sets `degraded = True` first — so
  the `question` assignment at `service_entry.py:106-107` is guarded by
  `not res.degraded` and can never fire. Verified live with `max_hops: 0`:
  `{"status":"need_input", "degraded":true, "hops":[]}` — **no `question` key**, so
  the extension renders "need_input", prints no question, and tells the model to
  answer `params.answer` for a question that was never asked.
*Minimal fix:* pass an `on_ask` from the HTTP layer that returns the question body
as data (`status:"need_input"` without executing), and delete the placeholder
branch.

**6. [major] `do_POST` has no input handling: invalid JSON produces no response, and
the body size is whatever the caller claims.**
`api.py:25-26`:
- `json.loads(self.rfile.read(length))` raises `JSONDecodeError`, which
  `BaseHTTPRequestHandler` does not catch — the handler thread dies, the connection
  closes, and the client sees an empty reply. Measured: `curl -d 'not json at all'`
  → `HTTP 000`, curl exit 52, and a full traceback on the service's stderr.
- `length` is trusted with no cap, so `Content-Length: 2000000` with 40 bytes sent
  pins a worker thread until the client gives up (measured: 4 s client timeout, no
  server-side timeout). `ThreadingHTTPServer` spawns a thread per connection and
  there is no pool limit, so this is an unlimited-concurrency door.
- A request without `Content-Length` (chunked) is read as zero bytes and answered as
  `empty intent` rather than rejected.
*Minimal fix:* wrap the read/parse in try/except returning `400`, cap the body
(length and a hard `read(min(length, MAX))`), and run under a bounded thread pool.

**7. [major] `filesys_glob` walks unbounded and can walk into a network mount.**
`impl.py:61-79` calls `_walk` (`impl.py:32`, `os.walk` with no depth limit) and
appends every match: no cap on hits, no depth limit, no timeout, no symlink guard,
and `SKIP_DIRS` covers `node_modules`/`.git`/`build` but not `mnt`. Measured:
`**/*` from the repo root → 171 hits in 0.00 s; from `/usr` → **199 016 hits in
4.4 s**, held in memory and returned whole. On this box the same op pointed one
directory up from `~/mnt/bench-host` walks an sshfs mount (documented hangs of 22 min
to 9.8 h), so a `path` param or a digest `cwd` of `~` is enough to wedge a worker
thread permanently. The path is LLM-supplied and only `os.path.isdir`-checked
(`scope.py:80-84`).
*Minimal fix:* a `conf` cap on entries (and a stop at cap), a depth limit, skip
`mnt`/remote filesystems, and a wall-clock bound in the walk.

**8. [major] The hops log is CWD-relative, and a non-writable CWD fails every op.**
`conf/defaults.json` → `hops_log.path: "service/logs/hops.jsonl"`; `log.py:19`
expands `~` only, so the path resolves against the process CWD (the extension
happens to spawn with cwd = repo root; a manual `python -m ti.http.api` from
anywhere else does not). Measured:
- run from a writable non-repo directory → `status:"done"` but hops written to
  `<cwd>/service/logs/hops.jsonl` (creates a stray `service/` tree wherever you
  launched);
- run from a read-only directory → **`status:"error", error:"[Errno 13] Permission
  denied: 'service'"`** — the telemetry side-effect takes the result down with it.
- `HopLog.path = "hops.jsonl"` (no directory) → `FileNotFoundError: [Errno 2] ''
  from `os.makedirs(os.path.dirname(path))` (`log.py:25`).
*Minimal fix:* resolve the path against the repo/config dir, guard `mkdir` for an
empty dirname, and make logging failures non-fatal (try/except around `append`).

**9. [major] `filesys_grep`'s `glob` param is an unescaped regex, and the obvious
form crashes the op.**
`impl.py:99`: `re.match(params["glob"].replace("**", ".*"), f)`. A caller passing
the natural glob form gets a regex error: `glob="*.md"` →
`error: nothing to repeat at position 0`, so the parameter is unusable in the form
any caller would write it (the only value that works is a bare regex such as
`".*"`, which then matches every file and is not a name filter at all).
Any LLM-supplied `pattern` is compiled raw and unguarded
(`impl.py:93`), so a pathological regex is a ReDoS against the service, and an
invalid one (`"(unclosed"` → `missing )`) aborts the op. Two more defects in the
same function: `files[:50]` (`impl.py:97`) silently truncates large directories
with no indication, and the `len(hits) < 200` cap (`impl.py:104`) is checked but the
walk continues to the end, so the cap costs full traversal anyway. It also uses a
bare `os.walk` with no `SKIP_DIRS`, unlike `filesys_glob`.
*Minimal fix:* reuse `_matched()` for the glob, bound the pattern length, cap hits
*and* `break` at the cap, and reuse `_walk`.

**10. [major] The extension spawns the service and never stops it.**
`lifecycle.ts:39-41` spawns with `detached:true, stdio:"ignore"` and `unref()`s it
(`lifecycle.ts:71`); `index.ts:325-328` (`session_shutdown`) only clears
`lastServicePid`. The service therefore outlives every pi session, and a second
spawn races the first: measured live, `python3 -m ti.http.api` on a taken port dies
with `OSError: [Errno 98] Address already in use` and a full traceback (`api.py:55`
has no handler). The only way to reclaim the port is the `kill <pid>` that `/ti`
prints. On this box an orphan from a *different* checkout was holding `127.0.0.1:1113`
for 7 h when this audit started; it is exactly what made the audit's own first
start attempt fail.
*Minimal fix:* write the child pid to a well-known file, kill on `session_shutdown`
(or `process.on("exit")`), and make `serve()` report a busy port as a one-line
error. Race-safe: an existing healthy `/health` should be adopted, not re-spawned.

**11. [major] `mode:"raw"` and the "soft context" half of the tool contract are not
implemented.**
Spec §3: `mode:"raw"` "returns un-summarized results", and "every other key
[that is not in the step schema] is passed to the decision model as soft context.
Unknown keys never fail a call." Reality:
- `mode` is read only for `plan` (`service_entry.py:33,37`); `raw` falls through to
  the normal path and returns the identical body (verified live — byte-identical
  result to `auto`). The extension's own help text (`index.ts:47`) advertises it.
- `validate_params` computes `soft` (`op_api.py:56`), the runner threads it through
  (`runner.py:103,107`), and the only consumer **logs** it
  (`service_entry.py:142`). `grep -rn soft service` finds no path into any state or
  prompt. So `useTool(..., {when: "last week"})` silently discards the constraint —
  the exact opposite of the "open-context semantics" the spec promises.
*Minimal fix:* either implement both or remove them from the contract, the spec and
the tool description; a documented no-op is worse than an absent feature.

**12. [major] The research pipeline is 4 of the 7 specified steps.**
Even after finding 3 is fixed, `research.py` has no per-page `noul:is_relevant`
verification with a k-good-pages stop (spec §7.5), no reddit cross-check gated by
step-1 classification (§7.6), and no assemble step producing "per-source claim
digest + link + confidence" (§7.7). `templates/__init__.py:16` makes the final
artifact the raw `pages` list. `research.good_pages_target` and
`research.query_count` exist in config but nothing reads them.
*Minimal fix:* add the verify and assemble steps; they are pure `Step` graphs and
the ops already exist.

**13. [major] The service-side digest bound has a hole.**
`context/session_digest.py:26-39` caps the two lists and `_clip_turn`
(`:50-56`) clips `summary` only — every other key on a turn is copied through by
`dict(turn)`. Verified: a turn carrying `{"blob": "X"*100000}` survives `sanitize`
at 100 093 chars. `docs/architecture.md` presents this function as the guarantee
that "worst case they get a thinner state, not a bigger one"; that holds only for
extension-shaped input.
*Minimal fix:* project each turn onto `{role, summary, mentions}` and drop the rest.

### Minor

**14. [minor] `confidence` is fabricated as 1.0 when nothing measured it.**
`service_entry.py:131-132`: `_route_conf` returns `1.0` when there are no decide
hops. Every listing, every error response and every L0 passthrough therefore reports
`"confidence": 1.0` — including `{"status":"error", "confidence":1.0}` (observed
live on the pair failure). The extension renders it as "route conf 1.00". Fix:
return `None` and omit the key.

**15. [minor] `validate_params` is not a schema validator.**
`op_api.py:49-60` checks key presence only — no types, no coercion, no ranges. A
`queries: 42` reaches `web_search`, which coerces; a `thread_cap: "many"` reaches
`int(…)` and raises. The docstring ("validates before calling") and spec §3
("schema-validate") oversell it. Fix: per-op type entries or a `TypedDict` check.

**16. [minor] Pre-gate kinds are half implemented.** `gates.py:4` advertises
`"exists"|"conf_gte"|"noul_gte"|...`; `check_pre` implements existence and
`conf_gte` only (`gates.py:32-38`). A template written against `noul_gte` would
silently never fire (unknown kinds are no-ops).

**17. [minor] `gate_noul` has no caller.** `policy/confidence.py:28` exposes it;
`check_post` uses a hardcoded `0.75` default (`gates.py:44`) and every gate that
sets a threshold sets its own literal. The config knob the spec calls out
("noul ≥ 0.75" in `conf`) is decorative.

**18. [minor] A single-candidate pick crashes the logit_read lane.**
`logit_read.py:60` raises `ValueError: need 2..20 options, got 1`. One candidate is
a legitimate state (a listing of one file, a filtered candidate set), and
`run_pick` happily produces it. Fix: return the sole option with conf 1.0 before
calling the model.

**19. [minor] `heuristic_micro` violates the primitive's return type.**
`heuristic_micro.py:25` is annotated `-> ChoiceAnswer` but returns `None` to
abstain. As the configured pre-gate that is handled
(`resolve.py:126-131`, `cascade.py:158-166`), but naming it in
`backends_in_use.choice` gives `'NoneType' object has no attribute 'probabilities'`
(verified). Fix: annotate `ChoiceAnswer | None` and reject it at `make_backend`
for the `choice` kind.

**20. [minor] The picker never checks that the model's answer is a candidate.**
`decisions.py:97-101` takes `answer.choice` / the top-k of
`answer.probabilities` with no membership test against `criteria`. A backend that
hallucinates an id yields `picked_items: ["made-up"]`, which then fails in
`filesys_read` as a confusing `FileNotFoundError`. `openrouter.py:139` guards
this internally; `d1_systemone.py:37-38` does not. Fix: filter picks against
`criteria` in `run_pick`.

**21. [minor] `_plan_view` reports `ops_available: true` unconditionally.**
`service_entry.py:175`. It is not a check of anything — the value is a literal —
and it certified the broken research plan in finding 3. Fix: compute it from
`all_ops()`.

**22. [minor] The reported `meta.level` is recomputed from a different input.**
`service_entry.py:102` calls `inspect(intent, params, {})` — dropping the digest
that the real dispatch used (`service_entry.py:35`). Today `inspect` ignores the
digest, so the two agree by luck; the moment L1 classification reads the digest
(spec P3) the reported level will diverge from the executed one. Fix: reuse `meta`.

**23. [minor] `filesys_read` reads the whole file to honour `max_lines`.**
`impl.py:85`: `[l for i, l in enumerate(fh) if i < limit]` — the comprehension
consumes every line and keeps 2000. A 10 GB file is a full read. Fix:
`itertools.islice`.

**24. [minor] `filesys_glob` reports conf 1.0 regardless of hits.**
`impl.py:77` returns a constant `1.0`, including for zero matches, so the conf
axis carries no information for this op and a downstream `conf_gte` gate can never
catch an empty listing.

**25. [minor] Dead code.** `context/packer.py:22` `pack()` and `:35` `trim()` (only
`tests/test_skeleton.py:75` calls `pack`; `trim`'s accounting is also wrong — it
pops a key, then re-adds it as `"(trimmed)"`); `session_digest.py:60`
`mentioned()`; `resolve.py:152` `decide_factory()` and `:157` `as_state()`;
`planner/free.py` (the whole file, as specified); `http/api.py:12` imports `os`
unused; `templates/__init__.py:35-36` is marked `# pragma: no cover` and is
genuinely unreachable. None of it is load-bearing; all of it will be copied by the
next reader.

**26. [minor] `conf.load()` returns a mutable global without a lock.**
`conf/__init__.py:30-43`. `cascade_cfg`/`pair_cfg`/`cache_cfg` copy defensively,
which is evidence the authors hit this; `d1_systemone.py:20` and
`logit_read.py:28-29` hold nested references. Under `ThreadingHTTPServer`, a
handler that mutated the dict would change every other thread's config. The
double-checked init is also unsynchronised (benign — both threads build an equal
dict). Fix: return a deep copy, or document the dict as read-only and lock `load`.

**27. [minor] `jev_api` is in the spec and nowhere else.** `spec/1.0-spec.md:91`
lists it among the backends; `grep -rn jev_api` finds only that line. Spec §5 says
"reserved", but nothing in the tree reserves it — there is no file, no registry
entry, no test. Either add the thin adapter or mark it explicitly as v2 in the spec.

**28. [minor] `hop` accounting is off by one and `Budget.degraded` is unused.**
`budget.py:20-23` increments then raises when `hops > max_hops`, so `max_hops`
counts *completed* hops and one extra is attempted; `budget.py:40`'s `degraded`
property is never read. Cosmetic, but it means `max_hops: 24` permits 25 attempts.

**29. [minor] `noul` post-gate blocks can never be resolved by an answer.**
`runner.py:166` only re-writes an artifact when `gb.detail` carries an
`"artifact"` key; `check_post`'s detail is the verifier cond (no such key)
(`gates.py:42-44`). A post-gate ask therefore always lands in "answer not
applicable" and the step proceeds unverified.

**30. [minor] The extension's client timeout is shorter than the service's own
budget.** `bridge.ts:36` defaults to 120 s (`index.ts:12`), `conf.budget.max_seconds`
is 180 s. A run the server intends to finish is abandoned by the client first, and
the error the model sees is "timeout" rather than the server's own degraded result.

**31. [minor] Documentation drift.**
`README.md:21-22` says "Status: Skeleton + spec … Nothing is wired end to end yet",
which is false in both directions — there is a working L0/L1 path *and* the headline
L2 path is broken; a stranger cannot tell which. `spec/1.0-spec.md:119` names
`pi-extension/src/useTool.ts`, which does not exist (`src/index.ts`).
`docs/ops.md:152` reads "lives on an external mount (an external mount)" — a
duplicated parenthetical where a path was redacted. `docs/testing.md:53`'s
"~1.7 s per routing decision" is the only latency figure a reader can find; the
measured p50 in `docs/decision-pair-vs-hosted.md` is 3.1 s for the shipped pair.
