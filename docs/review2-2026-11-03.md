## Verdict

The engine got better and the delivery surface got real. Three of the five blockers are
genuinely fixed with tests that would catch a regression; one is fixed in structure but
still has two holes, one entry point at a time; one was fixed at the run level and
deliberately left open at the op level, with a doc that says so.

The merges also left four new breaks: **the ReDoS guard is bypassable** (measured,
end-to-end, over HTTP), **the deny list is not honoured on `params.path`** (measured: one
unconfined `stat`), **`bench/live_e2e.py` now rejects the service's own response bodies**
(measured, so the probe that "proves the shipped path" fails on correct behaviour), and
**`ops.filesys.roots` ships as `~`, so every session whose cwd is outside `$HOME` gets a
403 on every call** (measured at the boundary). The first two are holes in machinery that
had not existed before the repair; the last two are consequences of merging branches that
each changed one half of a contract.

Counts: **4 blockers, 6 majors, 10 minors.**

## New blockers

### NB1. The ReDoS guard refuses four shapes and lets a bounded quantifier through: `(a+){10}b` wedges the worker

`service/ti/ops/filesys/regexguard.py:240-248` calls `_refuse_unsafe` **only when the
quantifier is unbounded**:

```python
    unbounded, nxt = _read_quantifier(pattern, index)
    if unbounded is None:
        return False, index, prev
    atom = prev if prev is not None else _emit(frame, _ANY, index)
    if unbounded:
        _refuse_unsafe(frame, atom)          # <- `{10}` never gets here
        atom.unbounded = True
```

`_read_quantifier` (`:285-289`) reports `{n}` as **bounded** (`return endswith(",}")` is false
for `{10}`), so the nesting rule at `:252-256` — the rule whose whole purpose is
`(a+)+` — is never consulted for `(a+){10}`. The same hole covers `(?:a+){10}`,
`(?=(a+){10})` and `(\w+\s*){8}`.

Measured on the shipped config (`line_max_chars` 400, `deadline_s` 5.0):

```
(a+)+b     -> refuses, "backtracks exponentially"
(a+){10}b  -> ACCEPTED:  24 chars 0.13s | 28 chars 0.78s | 32 chars 3.78s | 36 chars 19.88s
                         40 chars TIMEOUT>25s | 60 chars TIMEOUT>25s
```

and end to end through the registered op, over HTTP, against a file with one 28-character
line (L0 is allowed to call `filesys_grep`, and `pattern` is the caller's):

```
pattern 'needle'       HTTP 200 status=done      3.1 ms
pattern '(a+){10}b'    HTTP 200 status=done    854.8 ms      <- 275x on a 28-byte file
```

and at the line width the op actually permits, through `get("filesys_grep").run`:

```
filesys_grep with (a+){10}b over ONE 400-char line: STILL RUNNING after 40s
(ops.filesys.deadline_s = 5.0, ops.filesys.grep.line_max_chars = 400)
```

Failure scenario: an authenticated caller (the LLM, picking its own `pattern`) sends
`(a+){10}b`, and the handler thread spins inside `re` with no budget; the deadline at
`impl.py:182` is only checked *between* lines, so nothing in the process can stop it, and
the 16-slot pool loses a worker per request until the service is restarted. The first review
measured this class at 25 s and the fix closed the patterns it named, not the property.

Minimal fix: refuse any *quantified* nested atom, bounded or not — in `_take_quantifier`,
`if atom.nested: _refuse_unsafe(frame, atom)` regardless of `unbounded` — and add
`(a+){10}b` to `tests/test_filesys_bounds.py:249` (which today only pins `(a+)+$`,
`a*a*b` and `(a|aa)+b`, i.e. exactly the four shapes the doc names).

### NB2. The deny list is not honoured on `params.path`: one unconfined `stat` before any refusal

`service/ti/planner/scope.py:79-84`:

```python
def _existing_dir(name: str, frame: str) -> str | None:
    path = os.path.expanduser(name)
    if not os.path.isabs(path):
        path = os.path.join(frame, path)
    path = os.path.abspath(path)
    return path if os.path.isdir(path) else None      # <- a stat, with no confine call
```

`os.path.isdir` is a `stat`. It is reached from `disk_lookup._listing` → `scope.resolve` →
`_scoped`, with `name` taken from the caller's `params.path` or from a directory named in
the intent (`scope.py:53-56,63-71`). The HTTP boundary does not check it:
`api._check_path_args` (`http/api.py:187-208`) only inspects `params.tool`'s path arguments,
i.e. the L0 route, so a plain `params.path` reaches the planner untouched. Same value, two
fields, two different answers:

```
params.path=/etc  (outside the policy roots)  HTTP 200 status=error
   err = "/etc resolves outside the permitted root ..."      <- the op refused it, afterwards
digest.cwd=/etc   (same value, other field)   HTTP 403 scope_refused   <- refused at the door
```

and with a deny root stood up in `/tmp` (nothing near the real mount was touched):

```
deny roots in force: ['/tmp/ov2-deny-.../deadmount']
scope.resolve("list the files in the directory", {"path": DENIED}, {"cwd": ROOT})
   -> Scope(frame=..., root='/tmp/ov2-deny-.../deadmount', named=None)
   os.path.isdir calls: ['/tmp/ov2-deny-.../deadmount']       <- the stat the deny list forbids
confine.resolve(DENIED) -> refused: "is at or under a denied root"
```

Failure scenario: on this box the deny root is `~/mnt`, an sshfs mount whose FUSE session
dies periodically; a single request naming it in `params.path` performs the one syscall that
blocks in uninterruptible sleep, and `timeout`, the tool harness and `SIGKILL` all fail to
release the resulting thread — measured on this box at 22 minutes to 9.8 hours. Everything
downstream then refuses correctly, which is exactly why the bug is invisible: the refusal is
in the log and the hang is not.

Minimal fix: `_existing_dir` calls `confine.resolve(name, base=frame)` and returns `None` on
`PathRefused` (a path outside the run root is "not a directory here", which is already the
shape of the answer `scope` gives), and `api._use_tool` checks `params.path` against the run
root the same way it checks `digest.cwd` at `:162-165`.

### NB3. `bench/live_e2e.py` now rejects the service's own bodies — the probe that "proves the shipped path" fails on correct behaviour

Two hand-merged branches disagree about the contract, and the newer one encodes the older
rule. `bench/live_e2e.py:203-206`:

```python
    confidence = body.get("confidence")
    if confidence is None:
        if status in ("done", "need_input"):
            problems.append(f"status {status!r} with no confidence (service_entry always sets one)")
```

and `:186-188` treats a `null` hop conf as a type error. Both are what the merged service

Measured against the real bodies:

```
   contract problems: ["status 'done' with no confidence (service_entry always sets one)"]
L1 listing: status=done conf=<absent>
   contract problems: ["status 'done' with no confidence (service_entry always sets one)"]
research-shaped body, hop conf null:
   ['hops[0].conf is None, not a number']
```

Failure scenario: `python3 bench/live_e2e.py --serve` — the command `docs/live-e2e-2026-11-03.md`
gives as "the acceptance test this audit is really about" — now scores cases 1, 3 and 4 as

service violates two of them.

### NB4. `ops.filesys.roots` ships as `~`, so a session outside `$HOME` gets a 403 on every call

`service/ti/conf/defaults.json` → `ops.filesys.roots: ["~"]`, enforced at
`http/api.py:162-165` via `confine.confined_root` (`confine.py:140-164`). Measured live, with
the service's own cwd in `/tmp`:

```
{"intent":"read the file we discussed"} -> HTTP 403 scope_refused:
  "run root '.' is outside the permitted roots ('$HOME'); ops.filesys.roots is what widens this"
```

Failure scenario: `digest.cwd` is the pi session's cwd (`session_push.ts` → `ctx.cwd`), so a
session started in `/tmp`, `/srv`, `/opt`, `/var` or a checkout under another user gets
`403 scope_refused` on *every* useTool call — L0, L1 and L2 alike — where before the fix the
same call worked. Nothing in the tests catches it because `test_http_bounds.py:73-75`
overwrites `roots` with a temp dir (necessarily: `tempfile.mkdtemp()` lives in `/tmp`), so
the shipped default is never exercised through the HTTP boundary by the suite.

Minimal fix: ship `roots: ["~", "/tmp"]`-style breadth or, better, make the policy "the cwd
the caller states, minus the deny list" and keep `roots` as an optional narrowing — then add
one test that starts the server with the *shipped* conf and asserts a 200 for a temp-dir cwd.

## Majors

**M1. Sixteen half-open POSTs wedge the entire surface, `/health` included, and no token is
needed.** `pool.py:43-57` takes a semaphore slot *before* the handler runs, so authentication
happens after admission; `Handler` sets no `timeout` (`api.py:76-78`), so `self.rfile.read
(length)` at `:141` blocks forever on a body that never arrives. Measured with 18 sockets
declaring `Content-Length: 262144` and sending nothing:

```
opened 18 half-open POSTs declaring 262144 bytes
normal request -> HTTPError 503 {"error": "busy", "detail": "the service is at its concurrency ceiling"}
after closing them, /health -> 200
```

Because `/health` shares the pool, `ensureService()` reads the service as down and spawns a
second one, which fails with `EADDRINUSE` and is reported as `spawn-failed` — so an
unauthenticated local process can make the extension believe the product is broken. Fix:
`Handler.timeout = 10` (set in the class body; `BaseHTTPRequestHandler.setup` applies it to
the socket) and take the slot after the request line and headers are read.

**M2. The inspector routes a local file open into a web research run — five plausible intents.**
Rule order is R1 op → R1.5 research verb → R2 reddit → R3 web channel → R4 external source →
R5 research frame → default disk (`inspector.py:168-190`). R3 is deliberately never gated
(`:35-37`), and its TLD clause `\b[\w-]+\.(?:com|org|net|edu|gov|io|ai|dev|ca|onion)\b`
(`:102`) matches a *file* whose name contains a dotted segment. Measured through
`/v1/useTool … mode:"plan"`:

```
'open tsconfig.dev.json'                 WEB_CHANNEL   L2 research -> decide_extract, web_search,
                                                          decide_pick, web_fetch, digest_assemble
'read the wrangler.dev.toml'             WEB_CHANNEL   L2 research
'check the model.ai config'              WEB_CHANNEL   L2 research
'list the files in app/r/'               REDDIT_ROUTE  L2 reddit_digest -> reddit_digest   (hard error here)
'open lib/r/parser.rb'                   REDDIT_ROUTE  L2 reddit_digest
```

Failure scenario: "open tsconfig.dev.json" spawns the web CLIs, pays a search and a fetch,
and returns a digest of web pages about nothing the caller asked about — where the correct
answer is a `filesys_read`. R2's `\br/` (`:83`) has the same shape for any project with a
directory named `r`. Fix: gate R3 on `not _strong_local(text)` like R4/R5, and require R2's
`r/` to be preceded by whitespace or start-of-string (`(?:^|\s)r/`). The operator's own 11
recorded intents still route to `disk_lookup` (verified against `service/logs/hops.jsonl`),
so this is a new false positive introduced by the routing fix, not a regression of it.

**M3. Ask-back over HTTP throws away the work it just did, and the retry pays for it again.**
`service_entry.py:159-164` rewrites a `done` run to `need_input` while keeping `result`; the
extension's renderer takes the `need_input` branch and never prints `result`
(`index.ts:97-112`), so a research run that produced a four-source digest shows only the
question. The retry then re-plans from step 0 — there is no session state on the server
(`_run_steps` builds a fresh `ArtifactStore`) — so `decide_extract → web_search →
decide_pick → 4 × web_fetch` runs a second time. Measured cost of one L2 pass in the
project's own doc: 16–55 s and four CLI fetches. Fix (product decision, but state it): either
carry the digest through the question (`question.work = result`) and render it, or make the
retry resumable by keying the store on a run id the caller echoes back.

**M4. The extension adopts any service that answers `/health`, cannot tell whether it holds
its token, and its own diagnostic cannot see the problem.**
`lifecycle.ensureService()` returns as soon as `health()` answers
(`lifecycle.ts:51-53`), and `/health` is unauthenticated by design (`api.py:80-90`). On this
box port 1113 was held by another checkout's service for the whole review (pid 341888), and
that service 401s my token — a live demonstration of the split. Then: `serviceToken()` caches
whatever it reads (`token.ts:37-51`), `resetServiceToken()` has **no caller**
(`grep` over `pi-extension/` finds only its definition at `token.ts:54`), the bridge's 401
message always says "no token" even when a wrong one was sent (`bridge.ts:58-67`), and
`/ti doctor` decides everything from the unauthenticated `/health` (`index.ts:270-296`), so
it prints "service reachable" for the one failure it exists to diagnose. Fix: on a 401 from a
service you did not spawn, re-read the token file once (`resetServiceToken()` + retry) and
report "token mismatch" rather than "no token"; have `/ti doctor` make one authenticated
probe (a `dry=True` L0 call) instead of trusting `/health`.

**M5. `mode:"raw"` is still a no-op, and the extension's truncation notice still points at it.**
`_route` compares `mode` only against `"plan"` (`service_entry.py:66`), so a raw call returns
a byte-identical body:

```
mode auto == mode raw (minus timing/hops): True
```

Meanwhile `truncate()` (`index.ts:62-65`) clips every `done` result at `RESULT_CHARS = 1500`
and tells the model to "call useTool with mode:"raw" … for the full content". This mattered
less when the terminal artifact was a page list; it matters now, because the L2 terminal
artifact is a digest whose sources carry a 360-char claim each (`research.digest.claim_chars`,
`good_pages_target` 4). My fixture run, with pages clipped to 500 chars by the overlay, already
serialised to **1117 chars**; four real pages at `ops.web_fetch.max_chars` 20000 give
4 × (360-char claim + url + title + 4 fields) ≈ 2 KB plus the queries — comfortably past 1500.
Fix: honour `raw` by skipping `truncate` (and dropping `RAW_TIMEOUT_MS` to the same 120 s), or
delete the mode from the spec, the tool description and the notice.

**M6. The hop log — the dataset feeder — is written by the test suite.**
`hops_log.enabled` ships `true` with a cwd-relative path (`hops/log.py:15-27`,
`conf/defaults.json`), and only two test files turn it off. Measured: one `pytest` run
appended **73 records** to `service/logs/hops.jsonl` (75 → 148 lines), i.e. more than the whole
pre-existing file, every run. That file is gitignored, so it is the operator's live evidence,
and it is the reason `inspector.py:9-12`'s claim ("`service/logs/hops.jsonl` carries 16
distinct intents and the seven that ask for something off-disk") can no longer be verified
from the tree: the file now holds 11 intents and none of them is off-disk. The audit's finding
8 is also still open — `os.makedirs(os.path.dirname(path))` raises on a bare filename and a
read-only cwd takes the whole call down with it (measured again:

```
bare filename -> FileNotFoundError "[Errno 2] No such file or directory: ''"
read-only cwd -> PermissionError "[Errno 13] Permission denied: 'service'"
```

). Fix: resolve the path against the repo root, guard the empty dirname, wrap `append` in
`try/except` so telemetry can never fail a run, and default `hops_log.enabled` to `false`
under test (a `tests/conftest.py` overlay, not 20 call sites).

## Minors

1. `_plan_view` reports `ops_available: True` as a literal (`service_entry.py:246`) — it is
   not a check of anything, and the extension's plan renderer does not read it.
2. `meta.level` is recomputed by a second `inspect(intent, params, {})` that drops the digest
   the run actually used (`service_entry.py:152`), so the reported level and the executed one
   will diverge the moment classification reads the digest.
3. `confine.set_root` accepts a *file* as the run root (`confine.py:99-103`, no `isdir`), after
   which every path is refused except that one and `filesys_glob` reports an empty, complete

## Confinement probe results

Method: a throwaway tree in `/tmp/ov2/cf` (`root/` and `outside/` siblings), `set_root(root)`,
then `confine.resolve()` on each attack; the file's own contents distinguish a leak
(`SECRET`) from a refusal. Script `/tmp/ov2/probe_confine.py`, output verbatim above.

| attack | held? | why |
|---|---|---|
| symlink straight out (`a_link_out → outside/secret`) | **held** | `confine.py:271-274` refuses a target outside `root` before following it |
| two-hop chain (`b_link1 → b_link2 → outside`) | **held** | the loop re-enters on each hop and the second target is refused |
| file through a symlinked directory out | **held** | same check, on the directory component |
| symlink loop (`d_loop → d_loop`) | **held** | `MAX_SYMLINK_HOPS` 32 (`:41,262-266`) |
| relative symlink climbing out (`../../outside/secret`) | **held** | target is joined to the link's directory and normpath'ed before the check |
| dir read through a relative symlink out | **held** | as above |
| `/proc/self/root/<outside>` via a symlink | **held** | absolute target fails `_inside` |
| `/proc/self/root/<outside>` as a path | **held** | lexical `_inside` refuses it first (`:207-209`) |
| symlink into root, then `../` out (`h_inner/../../outside`) | **held** | `normpath` collapses `..` before the hop resolver, so the escape is lexical and refused at `:207` |
| hardlink to an outside file | **LEAK (design limit)** | a hardlink is not a symlink, so the resolver returns it; reading it yields the linked bytes. Creating one needs ownership on the same filesystem, so this is a limitation, not an escape |
| 40-hop chain, all inside root | **held** | hop cap 32 |
| trailing component is a symlink out (`sub/l_tail`) | **held** | refused at the last hop |
| absolute `/etc/passwd` | **held** | `_inside` |
| `../../../etc/passwd` | **held** | `_inside` after normpath |
| empty string | **held** | `PathRefused("empty path")` (`:199-200`) |
| `inside.txt\x00../../outside/secret` | **held** | explicit NUL check (`:201-202`) |
| 5000-char path | **passes resolution** | resolves; the op's `open()` then fails `ENAMETOOLONG`, which is an error string, not an escape |
| `//etc/passwd` | **held** | `_inside` |
| `<root>/../../outside/secret` | **held** | `_inside` |
| trailing slash (`sub/`) | **held** | resolves to `sub` |
| `~/mnt` expressed as a relative climb | **held** | `DeniedPath` (`:224-228`) |
| a `cwd` pointing at a *file* | **accepted as a root** | `set_root`/`real_root` (`:99-103,167-185`) never checks `isdir`; the run then confines everything to that file, and `filesys_glob` returns an empty listing with **conf 1.0** because `walk` swallows `NotADirectoryError` (`walk.py:106-110`) |
| resolve→open race (TOCTOU) | **not defended** | the resolved string is handed to `open()`; a same-user swap between the two escapes. Inherent to path-based confinement; worth a line in the docstring rather than a fix |

Two notes the table cannot show, both verified by reading and one by mutation:

- The `..` branch inside `_resolve_hops` (`confine.py:249-252`) is **dead code**: `resolve`
  normpath'es at `:205` and `real_root` at `:181`, so no `..` ever reaches the loop.
  Replacing the branch body with an unconditional `AssertionError` leaves **588 tests
  passing**. Consequence: `..` is collapsed *lexically before* symlinks are resolved, which
  is not realpath's order (`/a/link/../x` is `/a/x` here, `/a/...`'s real parent there) — it
  makes the resolver stricter, not weaker, so it is safe, but the docstring at `:26-29`
  describes an algorithm the code does not run.
- Removing the deny check before each `lstat` (`confine.py:253-256`) breaks **no test**. The
  property the module is built around — "the refusal happens before the first syscall" — is
  asserted in prose, untested by the suite, and violated on the `params.path` entry point
  (NB2). That is the shape of a bug that survives a review.

**Verdict: nothing got out through `confine`.** Every path-shaped attack I could construct is
refused before it escapes, including the ones the module's own docstring claims. The two
things that did get out of the *system* are NB1 (a regex, not a path) and NB2 (a `stat`
performed by a caller the resolver was never asked about).

## What is genuinely good

1. `confine.py` is the right idea implemented honestly: a component-at-a-time resolver instead
   of `realpath` precisely because `realpath` would itself enter the deny root, with the
   reasoning written down at `:23-29`, and it holds against every attack I could build.
2. The B3 fix is defence in depth done properly — the server's `K<2 → 1.0` sentinel is
   *preserved* where it belongs and the gate-side entry point refuses the shape, with a
   comment in each place explaining which is which; the mutation that looks right and changes
   nothing (B3') is the proof.
3. `digest_assemble` is a real terminal step: rule-derived claims, per-source evidence grading,
   coverage-as-confidence, empty digest → conf 0.0 rather than a happy zero, and the reasoning
   for "no model call here" written down (`ops/research/assemble.py:1-31`).

   producer, classifies it measured/derived/asserted, and names the one it left undone instead
   of quietly leaving it — that is the standard the rest of the code docs should meet.
5. `tests/test_research_template.py:60` fixes a *class* of bug (every template × every op ×
   every required param), which is why B1 cannot come back, and the mutation table above shows
   the same instinct in `test_candidate_bound` and `test_confidence_honesty`.
